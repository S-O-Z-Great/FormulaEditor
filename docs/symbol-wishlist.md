# 符号清单与输入方案（待定义）

> 用途：把常用数学 / 化学 / 物理符号整理成一份可逐条勾选的清单，由你定义每个符号的**触发码**
> （即编辑区里 `#` 之后紧跟的那串字符），定义完成后统一并入 `src/symbols.js`。
>
> 本文件是**工作底稿**，不参与运行时。并入 symbols.js 之后，本文件转为归档记录。

## 一、填写约定

| 项 | 说明 |
| --- | --- |
| 编号 | `M` 数学 / `C` 化学 / `P` 物理，编号固定，按编号回复即可 |
| 触发码 | 键 `#` 之后紧跟的内容。1–3 个字符最好记（希腊字母那种全拼也可以） |
| 回复格式 | 随意，例如：`M01 用 r`、`M02=r`、`M03 #sq`（带不带 # 都行） |
| 批量 | 一次给几条、几十条都行，我按批回填 |
| 暂不定义 | 回 `M07 -` 或直接跳过，标为「不收录」 |

### 命名风格（已定，后续新码照此取名）

| # | 规则 | 例 |
| --- | --- | --- |
| 1 | **图形拼装**：符号长什么样，码就写什么样 | `(S)` ∮、`(/)` ∅、`(-)` ∈、`!6` ∂、`(o)` ⊙ |
| 2 | **ASCII 箭头**：方向靠 `<` `>` `=` 组合 | `<=` `>=` `=>` `<=>` `->` |
| 3 | **小词语义**：常用英文小词直接当码 | `in` `so` `bc` `lim` `sum` |
| 4 | **`!` 表翻转 / 取反** | `!A` ∀、`!D` ∇、`!(-` ∉、`!=` ≠ |
| 5 | **`^` 放码尾 = 盖帽子**，其他标注同理走后缀 | `#H^` Ĥ、`#alpha^` α̂、`#x——` x̄ |
| 6 | **直观优先**：新码不必避让旧码 | 补集 `C`（与组合数同码，候选区分）、厄米 `+`（不用 `!+`）、平均 `——` 后缀（不用 `bar`） |

第 6 条是本轮定下的取舍：**触发码的价值在「好记」，不在「唯一」**。撞码交给候选条（E11）解决，
不要为了避重把直观写法改成需要背的缩写 —— 需要避重时应让**次码 / 别名**去承担，主码永远留给最直觉的那个。

### 触发码匹配规则（引擎现状）

- 按**前缀**匹配，同前缀按时长排序，`canExtend` 为真时继续等输入，不会立刻提交。
- 因此 `#si` 可以同时容纳 `si`（sin）和 `sinh`，短的不会被长的挡住。
- 大小写敏感：`#S`（积分）与 `#s` 是两条不同的码。

### ⚠️ 已被占用的触发码（新码请避开）

```
结构    --    ——
运算    /     *
关系    =     ~
集合    U     n     A     E
微积分  S     s     II
导数    '     ’
希腊    alpha beta gamma delta epsilon zeta eta theta iota kappa lambda mu
        nu xi omicron pi rho sigma tau upsilon phi chi psi omega
        Alpha Beta Gamma Delta Epsilon Zeta Eta Theta Iota Kappa Lambda Mu
        Nu Xi Omicron Pi Rho Sigma Tau Upsilon Phi Chi Psi Omega
```

注意几处「形近抢位」：`U`/`n`/`A`/`E`/`S` 已被集合与积分占用，所以物理里 `U`(内能)、
`n`(摩尔数)、`A`(面积)、`E`(能量)、`S`(熵) 这类单字母码需要换写法（如 `En` `mol` `Ar`）。

## 五、定义过程中产生的引擎需求

> 有些符号不只是「插入一个字符」，而是要求引擎改变行为。这些单独记录，待并入时一并实现。

| # | 来源 | 需求 | 说明 |

| E1 | M18 极限 | 算子型符号的槽位模型 | `lim` / `sum` / `prod` / `int` 这类应识别为**算子**：符号体本身不可编辑，其后（或正下方）挂若干空槽作上下限，槽内可写任意式子（如 `x→0`）；槽填完 Tab/回车后光标回到主体基线继续写。对应 `\lim_{x\to0}`。 |
| E2 | 全局 | **三前缀分立**：`#` 运算符 / `@` 变量 / `$` 元素 | 原本 `##x##` 一个写法背两种含义（变量模式 / 运算符级升级），只能靠上下文猜。现在拆成三个互不重叠的起手符：`#` 走符号表（运算符、结构、符号），`@` 进变量主体，`$` 进元素主体。三者统一为「起手符 + 名字 + 收尾符」，各认自己的收尾符（`@Tom@` / `$Cu$`），`@` 与 `$` 另外接受 Tab / Enter。旧的 `##Tom##` 保留为兼容写法，行为一字不改。 |

## 第 18 批已实现（块边界插入）

反馈：「在元素符号的左边输入会输入进同块中，这不合理，一个块理论上只管一个元素符号」。

复现（`test/edge.probe.js`）：`$Cu` 收尾后一路 ← 走到块左边界（`pos == unit.start`），
打一个 `x` → 整体从 `\htmlData{fe=elem}{…}` 变成 `\htmlData{fe=elem}{x{phantom{0}}…}`，
`units()` 还是一个，`x` 成了块里的第一个字。后果和「一个块两个符号」一样：删一次走两个、
四个槽整体串位。`#al` / `@Tom` / `#v` 在这个位置上也会被吞进块里。

根因（实测，不是猜）：
- MathLive 的插入语义是「在 `at(position)` 那个原子**后面**插」；
- offset 是后序编号，整体内部第一个原子的 offset **正好等于**整体自己的 `start`；
- 所以「紧贴整体左边」和「整体内部最左一格」是同一个数，`insert` 必然解析成后者。
  这不只是 `\htmlData` 的问题——任何有 body 的原子（分式、根号）左边界都这样，
  只是我们的整体左边界最常被光标点到。

做法（`renderer.js`）：

| 函数 | 作用 |
| --- | --- |
| `leftUnitAt(pos)` / `atUnitLeftEdge(pos)` | 光标是不是正贴着某个整体的左边界：前者严格 `pos === u.start`（回删用），后者还接受 `pos === u.start - 1`（分式、根号这类结构性整体的最左一格前面还空着一格） |
| `insertBeforeUnit(tex, del)` | 在左边界落笔：取出整体 latex → **连待定码一起**按区间选走删掉 → 插新内容 → 整体原样插回 → 光标回到它的左边界。返回 `true` 表示已处理 |
| `jumpToSlot()` | 起点改成「提交那一刻的光标位置」，`moveToNextPlaceholder` 之后再把整格选中收成折叠插入点（`hi-1`） |

接线三处：`typeChar()`（普通字符与待定码逐字落地）、`replacePreedit()`（提交符号 / 变量 / 元素，
`del` 一起交给 `insertBeforeUnit`）、`handleKeyDown` 的普通字符分支（焦点在公式里时 MathLive 自己
处理按键，得在它前面拦下来）。

坑：

1. **不能只 `selectRange(u.start, hi)` 再 `insert`**：选区换成插入时，插入点还是那个歧义 offset，
   照样落进块里。必须先把整体**删掉**，光标才落在一个确定的外层位置，然后再插新内容、再插回整体。
2. **那个位置上的 `deleteBackward` 是空操作**（前面没有原子可删）。待定码回删因此改走区间：
   实测选区端点比原子右边界少一格，`[pos-n-1, pos)` 正好盖住光标前那 n 个原子。
   这条只在左边界生效（`leftUnitAt` 判定），其余情况仍用逐次 `deleteBackward`。
3. **待定码一个一个字插的时候，每次都要挪一次块**：插完就得把整体插回来，否则第二个字又落回块里。
   代价是每个字一次「取出 + 重新解析」，字数很少（触发码一般 2–5 个）可以接受。
4. **`getValue([start, end], 'latex')` 是安全的取整法**：带 `\htmlData` 外壳、带已填的槽
   （`^{14}` 原样保留），插回去还是同一个整体。`getValue(selection, 'math-ml')` 不行，
   它会吐 `<mi>\htmlData</mi>`。
5. **`jumpToSlot` 不能按 `docFields()` 找最近的空槽**：根号、`\begin{}` 的槽是 `body` 分支，
   不在字段表里，按表找会跳到隔壁元素的四格去。`moveToNextPlaceholder` 从提交位置出发才通用。
6. `insertBeforeUnit` 末尾把光标放回整体左边界后，这个位置仍然是「歧义位」——但没关系：
   下一次插入会被同一个判断接住，下一次删除走区间路径。行为是自洽的。
7. **`^` / `_` 不在处理范围内**：它们本来就该挂在左边那个实体上（H₂ 的写法），
   贴着整体左边界敲时 MathLive 会在整体内部塞一个空上下标。空壳不影响显示、
   不影响整块删除，暂留；真要做的话得先定义「没有底数的上下标」长什么样。

验证：新增 `test/edge.probe.js` **17 项**（块外字符 / 已填槽不动 / 符号码 / 待定码逐字退格 /
变量 / 结构 / 两块之间打字），并修了 `slotvis.probe.js` 里「分式插入后光标在分子槽」的期望值
（`pos` 3 → 2：现在是折叠插入点，不再是整格选中的右端点，另加一条「分子里确实进了 a」的断言）。
全量：`npm test` 89 项、`input` / `inline2` / `slots` / `core` / `sigil` / `unit` / `slotvis` /
`slotnav` / `compound` / `edge` 全过、`allcodes` 154 码全过。

**未随数学一起并入的几类**（等引擎能力）：
- 后缀修饰 10 条（`^` `——` `~` `.` `..` `>` `{` `}` `(` 粗体）—— 需要「取前一单元并包裹」（E13）。
  其中 `ob` / `ub` 暂留作过渡别名，E13 落地后删除
- `##Sigma` / `##Theta` —— **已定案并落地**（E16）：`##` 不是另一张表，就是把 `#` 走两遍，第二遍的触发码是**字符本身**（`Σ`→∑、`Θ`→⊖）。`symbols.js` 末尾「二次解析」组 + `engine.secondPass()`
- `#。` 度数 —— 输入法会把中文句号规范化成 `.`，实际打不出来，暂留 `degree` 与 `^o`

## 第 19 批已实现（整体左边的删除）

反馈：「删除左边的数字，会导致右边的元素符号被删除」。

## 第 20 批已实现（实体之间的符号）

反馈：「两个元素符号之间如果有其他符号，光标只会在该符号左右两边的元素符号间切换，
而越过了元素之间的符号，比如加号」。

复现：`$Cu +$O ` 得到 `…Cu…} + \htmlData{…O…}`，units = `[1,26)` 与 `[27,51)`，`+` 在 offset 26。
从 `O` 一路 `←`：`50 → 47 → 33 → 22 → 7 → 1`，`26`（加号）从来没停过；
`→` 同理从 `22` 直接跳到 `33`。

根因：跨实体只问 `fieldNext()`，它只看 `docFields()`（槽位表）。`+` / `=` / 数字不是槽，
表里根本没有它们，所以「实体之间」的这一步被整个跳过。

做法：

| 新增 | 说明 |
| --- | --- |
| `gapAtomNear(model, pos, dir, list)` | 遍历全部叶子原子的 offset，只保留「`unitOf()` 为空 **且** `fieldAt()` 为空」的（= 不属于任何整体、也不在槽里），取光标左/右最近的一个返回。不能只看最近的那个原子：光标在 `O` 里时最近的叶子是 O 自己的原子，跳过它继续往外找才找得到 `+` |
| `tabGapPos(targetCaret, dir)` | Tab 用：只有当间隙原子落在「当前格与目标格之间」时才返回它，否则返回 null 走原来的跳格 |

接线：`handleUnitKey` 的方向键在 `fieldNext` 之前插一步（只对 `←` `→`）；
`handleTabKey` 的四个分支（前进 / 后退 / 列表首尾）各加一次检查。

限制：方向键的间隙停靠只在「光标在间隙里（`u` 为空）或在某个格里（`here` 非空）」时生效。
光标落在实体**主体**上时（`here` 为空、`u` 非空）不能跳——否则 `O` 右端按 `←` 会直接飞到 `+`，
O 的四个槽一个都走不到。

验证：新增 `test/gap.probe.js` **7 组 8 项**（`→` / `←` / `Tab` / `Shift+Tab` 经过 `+`、
两实体紧挨着时不多停、`=` 也经过、`2Cu + 3O` 每个数字各占一步）。
全量：`npm test` 89 项、12 个 probe 全过、`allcodes` 154 码 0 失败。

## 第 21 批已实现（格内逐字 + 外挂下标归属）

反馈：「还是槽位切换，现在是完全掠过了，导致如果我需要修改元素的槽位很不方便。
比如 H2+ 表示氢气+，我如果需要修改 2，但光标会直接从 + 的右边移动到氢气的左边，
但如果在 + 按下上箭头，则会跳转到槽位。修缮界面左下角的显示，现在不全，添加中英文输入法显示。
现在的页面空白很多，可以在空白处显示常用符号/希腊字母的输入方式，作为背景。」

### 1. 那个 2 为什么改不了

复现（`test/inside.probe.js`）：`$H_2+` 得到
`\htmlData{fe=elem}{…\mathrm{H}…}_{2+}`，光标停在 27，`←` 一步到 21（H 的电荷格）。

两个原因叠在一起：

1. **外挂下标没有归属**。MathLive 把「实体 + 紧跟的上下标」解析成**一个 subsup 外壳**：
   `\htmlData{…}` 在外壳的 `body` 分支里，下标是外壳的另一个分支。
   而 `docFields()` 只认「实体右边紧跟的**兄弟** subsup」（`lastUnit` 那条），
   外壳形态的下标于是 `unit` 为 `null`——既不算实体的格，也不在 `fieldAt` 里。
2. **格内多字时整格跳过**。这一格的 `leaves` 是 `[26, 27]`（`2` 和 `+`），
   光标在 27。方向键把「格里有字且没走到边上」判成「交回原生」，
   而原生 ← 会一步跳出整格（27 → 21），正好掠过 26。

做法：

| 改动 | 说明 |
| --- | --- |
| `unitInside(x)` | 从 subsup 外壳的 `body` 分支里把实体捞出来。有它就把这一格归给该实体并标 `external`；外壳的 body 进去时 `ext` 归零（里面那四格才是内层格） |
| `stepInsideField(f, dir, pos)` | 按这一格的 `leaves` 找「前一个字 / 后一个字」的边界，找到就自己 `selectRange` 折叠过去；找不到才交给后面的方位 / 间隙 / 跨实体逻辑 |

方向键的顺序变成：⓪ 格内逐字 → ① 实体内方位 → ② 实体的紧邻原子（`+` / `=` / 数字）→ ③ 整篇文档的下一格。

### 2. 底部状态栏补齐，加输入法徽标

- `#ctx` 不再「不在实体里就整块隐藏」：光标在正文里也写「正文 / 不在块里」并提示下一步能按什么。
- 页脚拆成两行：上行是状态（`#ctx` + 按键计数 + 提示），下行是按键提示 + 输入法徽标。
  原来挤在一行里，`#ctx` 会被 `text-overflow` 截掉半句。
- 按键提示补全：`#` 符号、`@` 变量、`$` 元素、`Tab` 换格、`←↑↓→` 换槽、`[` `]` 跳块、`Enter` 复制。
- **输入法徽标**：打拼音时（composition 事件）亮成「中文 · 蓝点」，停手 800ms 落回「英文」。
  浏览器读不到系统的中英开关——那是 IME 自己的状态，页面无权查询；这枚徽标看的是
  「此刻是否在组字」，这是唯一能拿到的确定信号。

### 3. 空白处的速查底纹

`#stage` 里加了一层 `.bg-hints`（`position:absolute; inset:0; pointer-events:none; z-index:0`），
内容全部由 `symbols.js` 生成——新增触发码自动出现在上面，不用维护第二份清单。

- 只收「一条命令对一个字符」的条目（`GLYPH` 表把 `\alpha` 映射成 α），
  结构类（`\frac{}{}`）画不出单个符号、函数类（`\sin`）本来就是正文字母，都跳过；
- 按组竖排成列（希腊小写 / 希腊大写 / 运算 / 关系 / 集合·逻辑 / 微积分 / 结构），
  每列一个 9px 的小标题，列内 `#al α` 左右对齐——像一张速查表，而不是一墙乱码；
- 整体 `opacity: .095`，再用径向遮罩把正中间（公式待的地方）淡出去，
  边缘清楚、中间不挡字；整块铺两遍，右边空出来的地方接着排。


### 4. 顺带修掉：新元素不许嵌进旧块

做截图时撞出来的：`$Cu` 把四格填完（质量数 14、质子数 29、电荷 +），接着敲 `$O`，
O 会落进 Cu 的 `\htmlData` **里面**——`units()` 只剩一个 `[1,52]`，
状态栏写「元素 1429Cu+O」，又是一个「一个块管两个符号」。

原因在 `startElem()`：它只做了一句 `moveAfterParent`。光标停在某个槽里时，
这句只把光标提到**那个槽的父级**后面，仍然在实体内部，所以拦不住。

改法：新增 `leaveUnit()`，起新元素前先问 `unitOf() || unitBefore()` 拿到当前实体，
把光标放到 `unitEnd(u)`（实体右边界）；只有本来就在实体外面时才退回 `moveAfterParent`。
变量（`@`）不做这一步——变量的槽里放变量是有意义的结构。
另一个坑：`leaveUnit()` 必须跳过「贴着左边界」的情况（`pos <= u.start` 直接返回），
否则它会把光标甩到实体右边，和 `insertBeforeUnit()` 抢同一件事——
`O|Cu` 想插在前面，结果 O 跑到了后面；`startElem()` 里因此也不能无条件 `moveAfterParent`。

### 2. 命令面板（`Ctrl` / `⌘` + `K`）

| 函数 | 作用 |
| --- | --- |
| `cmdkScore(it, q, qRaw)` | 打分：码相等 1200、码前缀 1000-len、码里含 820-len、LaTeX 名 700、中文说明 640、分组名 520；别名（`p:1`）-260，大小写照得上 +60 |
| `cmdkSearch(q, qRaw)` | 过滤打分、排序、截前 40 条 |
| `cmdkIdle()` | 空查询：先给「最近使用」（`localStorage: fe.cmdk.recent`），没有就每组取两条、跳过没有字形的结构类 |
| `cmdGlyph(x)` | 先试 `glyphOf`，结构类按命令名给替身：`\frac`→½、`\sqrt`→√、`\int`→∫、`\oint`→∮、`\sum`→∑、`\begin{cases}`→{、矩阵→▦ |
| `insertCmdk(it)` | **复用** `replacePreedit`，不写第二套插入 |
| `openCmdk / closeCmdk` | 打开前 `cancelIme()`（撤掉半截待定码），关闭后 `focusField()` |

键盘全在 `document` 的捕获阶段处理：面板开着时 Enter / ↑↓ / Tab / Esc / PgUp / PgDn 归面板，
其余字符原样交给输入框；`Ctrl+K` 开关面板，焦点在公式上或输入框里都有效。

坑：

1. **排序不能只按「前缀 + 长度」**：`al` 会因为 `#all`（3 个字符）比 `#alpha`（5 个）短而先给 ∀。
   别名条目在符号表里带 `p:1`，按它降权才对。engine 的 `query()` 早就有这条规则，面板这边要复刻。
2. **同分时大小写也要管**：`#Alpha`（拉丁 A）和 `#alpha`（α）小写后一模一样。

3. **不能另写一套插入逻辑**：面板插入必须走 `replacePreedit`，否则左边界挪块（`insertBeforeUnit`）、

4. **面板的按键要抢在 `inField` 判断之前**：`document` 的 keydown 是捕获阶段，
   输入框里的字符原本会被 `if (!inField && tag === 'INPUT') return;` 放行；面板分支必须写在它前面，
   且只 `stop` 自己处理的那几个键，剩下的 `return` 而不阻止，字符才进得去。

## 第 24 批（Word / WPS 的原生公式：一条走不通的路）

上一轮留下的话是「建议做 OMML：把 MathML 转成 OMML 塞进 HTML 剪贴板，粘进 Word 就是可编辑公式」。
实现完了，结论是**这条路在 WPS 上不通**，但过程里拿到了硬证据，也顺手修掉一个一直是坏的按钮。

### 1. MathML → OMML 转换器（`src/lib/mathml2omml.js`）

自己写，不引第三方：npm 上现成的 `mathml2omml` 是 LGPL，塞进项目不合适；
KaTeX 吐出来的 MathML 很规整，覆盖那个子集就够。UMD，node 单测与渲染层共用一份。

| MathML | OMML | 备注 |
| --- | --- | --- |
| `mfrac` | `m:f` / `m:num` / `m:den` | `linethickness=0` → `m:type=noBar` |
| `msqrt` / `mroot` | `m:rad` + `m:degHide` | 无次数时次数位留空 `<m:deg/>` |
| `msub` / `msup` / `msubsup` | `m:sSub` / `m:sSup` / `m:sSubSup` | |
| `mo` ∈ ∑∏∫∮⋃⋂ | `m:nary` | `limLoc`：求和 `undOvr`、积分 `subSup`；无上下限写 `subHide`/`supHide` |
| `mover`（重音） | `m:acc` | `‾` 走上划线 `m:bar`，不画小帽子 |
| `munder` / `mover`（非重音） | `m:limLow` / `m:limUpp` | `\lim` / `\max` 这类词单独走 `limLow` 并转正体 |
| `mtable` | `m:m` + `m:mr` | `m:mcs` 里写列数 |
| 配对括号 | `m:d` | 只在 MathML 标了 `fence="true"` 时才算，普通 `f(x)` 保持字符 |

两个只有「看兄弟节点」才能决定的事，放在序列层处理：
① 大运算符要把后面的内容收成 `m:e`，但遇到 `+` `=` `,` 就停，否则 `\int f + \int g` 会吞成一个；
② 左括号要找到配对的右括号才能变成 `m:d`，`\begin{cases}` 那种只有左花括号的，剩下的全归它。

### 2. 验证：OMML 本身是对的

把 8 条公式的 OMML 直接写进一个最小 `.docx`（`word/document.xml` 里放 `m:oMath`），
用 WPS 打开——**8 条全部渲染成原生公式**，分式 / 根号 / 定积分 / 求和 / 极限 / 括号套分式 / 矩阵都对。
截图存在 `docs/omml-docx.png`。所以转换器没问题。

### 3. 验证：剪贴板这条路不通

同一份 OMML 换个方式进 WPS，三种写法全试过：

| 写法 | 结果 |
| --- | --- |
| `text/html` = `m:oMath` + OMML 命名空间 | 粘进去是纯文字 `ab+x`（`m:oMath` 被当未知标签剥掉，只留 `m:t` 的文字） |
| 同上，但伪装成 Word 导出的 HTML（`ProgId` / `Generator` 元信息 + `mso` 条件注释） | 一样是 `ab+x` |
| `text/html` = MathML | 更糟：KaTeX 的 `<annotation>` 源码被当正文粘进去，成了 `ab+x\frac {a} {b}+\sqrt {x}` |

结论：**WPS 的 HTML 导入器根本不做数学转换**（Word 大概率同理，本机没装 Word 无法验证，
而且它的失败方式同样是「静默变文字」，不值得赌）。

### 4. 因此：Office 继续给图片，但修好「Word 公式」按钮

- 插件模式：WPS / Word / PPT 仍然只给**白底图片**——已验证、视觉 100% 正确。
- 独立编辑器的「Word 公式」原来塞的是 **MathML**，对 Word 而言从来就是坏的（只会粘出文字）。
  现在改成 `toWordHtml()` 输出真 OMML：有 OMML 命名空间、`m:oMath` 结构完整。
  Word 认不认还没法在本机验，但至少不比原来差，而且方向是对的。
- OMML 转换器保留，供以后「导出 .docx」用——那是唯一被验证能把原生公式交给 WPS 的通道。

验证：`test/omml.test.js` **63 项**并入 `npm test`（现在 89 + 52 + 63 = 204 项）。

## 第 25 批（让 WPS 真能用：按字号出图 + 前台锁）

### 1. 图片不能只有像素，还得有 DPI

贴进 WPS 的图早先固定 44px 高。Word/WPS 是按 PNG 里的 pHYs 分辨率换算显示尺寸的，
所以 44px 的图要么糊、要么大得离谱，用户还得手动拖图片角。

现在：渲染时固定 `cssSize = 100px` 铺版，量出公式**内容框**高几 em，
再按「em × 字号」算显示高度，最后写成 288 dpi 的 PNG（像素 = 显示尺寸 × 4）。
五号 10.5pt 的公式贴进文档正好一行高，不用调。

Electron 的 `toPNG` 不保证写 pHYs，自己往 IHDR 后插一段（`setPngDpi`），顺带删掉旧的。

### 2. 量高度量错了地方

一开始用 `#box`（inline-block）的 `getBoundingClientRect().height` 算 em 比例，
结果连一个「1」都被算成 1.24em——因为 inline-block 的高度被 `line-height: 1.2` 撑开了。
改成量 `box.firstElementChild`（MathLive 的 markup 根）的内容框，比例才对。

### 3. Windows 前台锁：SetForegroundWindow 会被静默拒绝

自动粘贴偶发 `nofocus`，根因不是句柄失效，是**前台锁**：不属于前台的进程调
`SetForegroundWindow` 会被拒绝，而返回值照样是 true。

修法：切之前先发一次 `keybd_event(VK_MENU)`（模拟用户按键，解除前台锁），
再 `AttachThreadInput` + `SetForegroundWindow`，然后**读回前台句柄比对**。
修完实测「记事本 → 酷狗 → 记事本」双向切换都成功。

注意 ALT 必须在 `AttachThreadInput` **之前**发：附着输入队列之后，这个按键会送进目标窗口、弹出它的菜单栏。

### 4. WPS 的 MainWindowHandle 不是能激活的那个句柄

`Process.MainWindowHandle` 对 WPS 拿到的句柄切不过去（文档装在框架窗口里）。
加了 `find <title>`：`EnumWindows` 遍历可见顶层窗口、按标题部分匹配，返回真句柄。
自检的 `--target-title=` 就用它自己找窗口、自己切前台。

### 5. 自检的安全阀

`--e2e=... --target-title=xxx`：前台窗口标题不含 xxx 就**一个按键都不发**，
直接中止。这一条救过一次——当时前台是用户的酷狗音乐，脚本本来要发 Ctrl+V。

### 6. 还没闭环的

WPS 的真机粘贴没能跑完：测试文档每次打开都被关掉，抢了几次焦点都扑空。
出图规格、焦点切换、剪贴板格式（`hasImage && !hasHtml`）都已单独验过，
最终「按 Ctrl+Alt+Q 在 WPS 里贴一次」留给用户自己确认。

## 第 26 批（「按了没反应」其实是从没起来：常驻启动 + 留痕）

### 1. 真凶不是热键，是进程早没了

用户反馈「WPS 里按 Ctrl+Alt+Q 没反应」。查下去发现：热键注册是成功的
（`registered=true`），但**进程根本不在了** —— 之前几次「重启」全是用 shell 后台
`npm start &` 或工具里的 `Start-Process` 起的，命令一返回，整棵进程树跟着被收掉。
托盘图标、热键、自动粘贴一起消失，用户那边表现就是「按了没反应」。

这也解释了更早那次「WPS 测试文档每次都被关掉」：不是用户关的，是窗口所属的进程被收走了。

### 2. 改成真正脱离终端的方式

- `start-plugin.vbs`：`WScript.Shell.Run`，窗口样式 0（隐藏），不闪黑窗口
- `start-plugin.cmd`：双击入口，只调 vbs
- 计划任务 `FormulaEditorPlugin`：登录触发，`Execute` 直接指向 `electron.exe`，
  参数 `.`，工作目录项目根 —— 它是 GUI 进程，跑起来本来就没有控制台

实测：启动后连续两个命令周期（间隔十几秒）进程仍是 5 个，热键按下去日志里
`hotkey fired → showPanel done host=WorkBuddy` 全在。

### 3. `start.log`：三行分辨卡在哪

`%APPDATA%\formula-editor\start.log` 现在记：注册结果 / 启动 / 热键触发 / 显隐。
排障时一眼能分清三种情形：

| 日志 | 含义 |
| --- | --- |
| 一行都没有 | 进程没起来 |
| 有 `start` 没有 `hotkey fired` | 起来了，但按键没到（前台锁 / 被别人抢了注册） |
| 有 `hotkey fired` 没有 `showPanel done` | 回调跑了，卡在显示（一般是等宿主超时） |

### 4. `combo` 命令 + `npm run test:hotkey`

要验证「按键到底能不能触发全局热键」，只有人按键盘能做 —— 于是给常驻助手加了
`combo ctrl+alt+q`（`keybd_event` 按顺序按下、逆序抬起），把这一步自动化。

`npm run test:hotkey` 用**另一个组合**（Ctrl+Alt+W）走完整链路：注册 → 模拟按键 →
等回调。它和正在跑的插件不抢注册，随时可跑。实测 PASS。

## 八、需回改的既有条目

> 这批定义会让 `src/symbols.js` 里已收录的条目产生冲突，并入时要一并改。

| 既有条目 | 现码 | 改为 | 原因 |
| --- | --- | --- | --- |
| 任意 ∀ | `A` | `!A`（主）/ `all`（别名） | `#A` 让位给排列数 A(n,k)，见 E5 / ③ |
| 约等于 ≈ | `~` | `~=` | 单键 `~` 太易误触，收紧成 `~=`；`#~` 之后会短暂等待 `=`（见 E6 / ⑥） |
| 大写希腊字母 Σ | `Sigma` | 保持 | 不回收：`#Sigma` 为 Σ，`##Sigma` 为 ∑，两者并存 |
| 连乘 ∏ | `II` | 待议 | 若按 E2 的两级逻辑，∏ 更该写成 `##Pi`（Π → ∏），`II` 可退役 |
| 补集 ∁ | `!C` | `C` | 改按命名风格第 6 条：直观优先，与组合数同码，交给候选条（E11） |
| 厄米共轭 † | `!+` | `+` | `+` 单键到位，† 本身就是个加号；不再借 `!` 翻转前缀（它语义是「倒 / 否」，不是「加」） |
| 二重积分 ∬ | `SS` / `s2` | `(SS)` | 统一进括号组合码（E4），三个码（`SS` `s2`）收成一个，顺带解决 `#S` 的前缀等待（E6） |
| 上括号 ⏞ / 下括号 ⏟ | `ob` / `ub` | `{` / `}` 后缀 | 归入后缀修饰族（E13），需要引擎先支持「取前一个主体并包裹」 |

> **本轮（第 10 批）修订汇总**：积分家族改成 `(S)` 括号计数（`(SS)` `(SSS)` `(Sn)`）、
> 上下括号改后缀 `{` `}`、平均值并入 `——` 后缀、补集改 `C`、厄米共轭改 `+`、
